# Internationalisierung

🌐 Sprachen: [Deutsch](I18N.md) | [English](../en/I18N.md)

## Sprachstandard

Deutsch ist die Standardsprache für README, Dashboard-Oberfläche, Standarddokumentation, CLI-nahe Statusmeldungen und menschenlesbare Fallbacks. Englisch ist die wichtigste Alternativsprache. Weitere Sprachen sollen ergänzt werden können, ohne die bestehende deutsche Standardroute zu brechen.

## Locale-Erkennung

Das Workbench-Dashboard nutzt diese Reihenfolge:

1. manuelle Auswahl im Browser, gespeichert als `workbench-locale`
2. `WORKBENCH_LOCALE` im Dashboard-Prozess
3. Browser- und HTTP-Sprache wie `navigator.language` oder `Accept-Language`
4. Systemvariablen wie `LC_ALL`, `LC_MESSAGES` oder `LANG`
5. stabiler Fallback auf Deutsch

Unbekannte oder nicht unterstützte Werte wie `fr-FR` fallen auf Deutsch zurück.

## Ressourcen

- Dashboard-UI: `Workbench/dashboard/static/locales/de.json` und `Workbench/dashboard/static/locales/en.json`
- Dashboard/API-Meldungen: `Workbench/dashboard/i18n.py`
- Deutsche Dokumentation: `docs/de/`
- Englische Dokumentation: `docs/en/`
- Deutsche README: `README.md`
- Englische README: `README.en.md`

Übersetzungsschlüssel sind punktgetrennt und nach Oberfläche gruppiert, zum Beispiel `nav.models`, `signals.connected` oder `state.saved`.

## GitHub

GitHub zeigt `README.md` als Repository-Startseite an und übersetzt diese Ansicht nicht automatisch nach Nutzersprache. Deshalb müssen mehrsprachige Markdown-Dateien sichtbare Sprachlinks enthalten. Die deutsche Datei bleibt die Standarddatei; englische Varianten tragen `.en.md`.

## Unicode und UTF-8

Alle relevanten Textdateien bleiben UTF-8. Umlaute, Akzente, Emojis, nicht-lateinische Zeichen und bidirektionale Texte dürfen in sichtbarer Prosa erhalten bleiben. Technische Tokens werden nicht transliteriert oder übersetzt, wenn sie Teil von Pfaden, IDs, API-Feldern, Befehlen oder Dateiformaten sind.

## Neue Sprache ergänzen

1. Neue Dashboard-Datei `Workbench/dashboard/static/locales/<lang>.json` mit denselben Schlüsseln wie `de.json` anlegen.
2. `SUPPORTED_LOCALES` in `Workbench/dashboard/i18n.py` und `SUPPORTED_LOCALES` in `Workbench/dashboard/static/app.js` ergänzen.
3. `docs/<lang>/index.md` und bei Bedarf weitere übersetzte Dokumentationsseiten anlegen.
4. Sprachlinks in README und zentralen Dokumentationsseiten ergänzen.
5. Tests für Locale-Erkennung, Fallbacks und Unicode ergänzen.
6. `python scripts/verify_openwebui_workspace.py` ausführen.

## Lokales Testen

```powershell
$env:WORKBENCH_LOCALE="en"
python -m unittest discover Workbench.dashboard.tests
python -m Workbench.dashboard.server --host 127.0.0.1 --port 8088
```

Im Browser kann die Sprache zusätzlich über die Auswahl oben rechts im Dashboard umgeschaltet werden.
